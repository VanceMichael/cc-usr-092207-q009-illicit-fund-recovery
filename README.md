# 涉案请托资金追缴协作

还原"找关系干预案件"类案件中涉案资金的拆分流转、证据状态与追缴结果，使跨单位协作始终围绕**同一笔钱**工作。

## 要解决的问题

一笔三百万元在多年时间线上交织着现金、转账、退回、截留、借款包装与警方扣押；同一笔钱在不同当事人嘴里可能是报酬、退款或借款。若按口供分别建表就会**重复计算**。本仓库用证据图把钱、说法、凭证和司法认定分层固定下来：

- **资金批次（fund batches）**是唯一参与求和的对象；每次交付、拆分、合并都是一个事件，消耗批次与产出批次**金额守恒**。
- **主张（claims）是附着在事件上的说法**，报酬/退款/借款并列留痕，永不并入金额；其翻转通过版本链保存。
- **司法认定（findings）只能由检察或审判主体作出**，扣押与退赔必须以 `confirmed` 等级入账；未经证实的主张与司法确认分字段展示，不混为一谈。
- **待核查线索（leads）不产生批次、不进入任何汇总**。
- 现金估算修正、证言翻转、案件移送、追缴对象变化、部分退赔都在 `revisions` 中留下版本。

## 资料结构

| 文件 | 作用 |
| --- | --- |
| `contracts/domain.schema.json` | 跨单位共享资料的结构契约（字段、枚举、必填项） |
| `fixtures/domain.json` | 匿名化示例：300 万的多年时间线（化名甲/乙/丙） |
| `src/domain.py` | 读取与校验：引用完整性、守恒、时序、版本链、认定权限 |
| `src/ledger.py` | 守恒账本：当前持有人、逐元追溯、追缴汇总、定性情形测算 |
| `src/access.py` | 阶段权限与视图投影（内部全图 / 财物管理 / 家属公开） |
| `src/report.py` | 命令行报告：每一元由谁持有、依据何在、是否已追缴 |

### 示例时间线（300 万元）

1. 甲向乙转账 200 万（凭证）＋交付现金，估算 120 万经取现记录**修正为 100 万**；
2. 乙向丙转账 160 万、现金 40 万（现金仅言词记录，可认定程度更低），截留现金 100 万；
3. 丙退回 100 万；乙向甲退回 60 万，另 40 万以**借条包装为借款**（乙还主张其为居间报酬）；
4. 侦查机关扣押丙 100 万、乙 50 万；期间案件**跨地移送**、追缴对象由丙扩展至乙；
5. 判决执行：扣押款中 100 万退赔甲、40 万没收上缴国库，乙线余 10 万仍在扣押账户待处置。

最终每一元都有归属：甲收回 160 万、国库 40 万、警方待处置 10 万、乙仍持 90 万待追缴。

### 不同法律定性下的待决定范围

情形只改变性质待定批次的归类，已司法确认的金额不随定性变化：

- 诈骗定性情形：违法所得待追缴 100 万，争议待定 0；
- 行贿关联定性情形：违法所得待追缴 60 万，以借条包装的 40 万性质争议、待审判决定。

## 权限模型

- 侦查、检察、审判人员按案件阶段（侦查→起诉→审判→执行）取得写入权限，全程可读全图；
- 涉案财物管理人员只见扣押、退赔、没收的执行信息与机构持有余额；
- 家属（依法查询的相关当事人）只见公开的退赔进度（日期、金额、渠道、公开说明），看不到证言、主张、线索或其他持有人。

## 本地校验与报告

```bash
python -m unittest discover -s tests   # 29 个测试：守恒、防重复计算、版本、权限、定性测算
python -m src.report                   # 逐元文字报告
python -m src.report --json            # 同一报告的 JSON 形态
```

仓库不保存账号、密钥、连接串或真实身份信息；示例当事人均为化名。
