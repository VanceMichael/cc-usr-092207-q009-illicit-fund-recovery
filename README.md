# 涉案请托资金追缴协作

还原涉案请托资金的拆分流转、证据状态与追缴结果。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括侦查人员、检察与审判人员、涉案财物管理人员、依法查询的相关当事人。

资料所依据的领域事实如下：

- 涉案三百万元经历多次退回、截留和扣押
- 现金与转账证据的可认定程度不同
- 报道中对部分行为的法律定性存在不同专业意见

## 资金台账与证据图

`fixtures/case.json` 是依照上述事实虚构的示例案件（请托人甲、中间人乙、关系人丙），以事件流记录三百万元的交付、拆分、退回、截留、借款包装、扣押、部分退赔与法院认定。`contracts/case.schema.json` 规定事件流结构。

- `src/model.py` —— 领域模型：资金批次、主张、证言、待核查线索；金额以分为单位
- `src/events.py` —— 事件类型：每一次资金或证据状态变化都是一条不可改写的记录
- `src/ledger.py` —— 台账：逐事件入账并强制守恒，全部变更留版本，可回放到任意事件序号
- `src/access.py` —— 阶段权限矩阵
- `src/report.py` —— 持有说明、退赔进度（家属可见）、待决定范围、证据图
- `src/case.py` —— 读取案件事件流并回放为台账

### 守恒规则

在册批次合计恒等于登记基准（交付登记累计 ± 现金估算修正）。拆分、退回、扣押、退赔、上缴只改变持有人与状态，不得改变合计；只有带凭证依据的现金估算修正事件可以调整登记基准，且修正前后金额都留在批次版本里。同一笔钱被不同当事人描述为报酬、退款或借款时，只登记为指向同一批次的主张，不重复建账；批次拆分后，指向它的主张、线索和追缴对象自动改指子批次。

### 主张与认定分层

主张（报酬、退款、借款等说法）与法院认定分开存放：主张只能登记、印证或因证言翻转降级，批次的法律性质只能由法院认定事件写入。查询结果中两者分别列示，未经证实的说法不与司法确认混同。

### 版本留存

现金估算修正、证言翻转、案件移送、追缴对象变化、部分退赔都会写入对应实体的历史，台账整体支持 `at_version(n)` 回放到任一事件之后的状态。

### 阶段权限

| 角色 | 可登记事件 | 有效阶段 |
| --- | --- | --- |
| 侦查人员 | 交付、拆分、退回、形态变更、现金估算修正、主张、证言翻转、线索、扣押、移送 | 侦查 |
| 检察人员 | 追缴对象变化、移送、线索 | 审查起诉 |
| 审判人员 | 法院认定、移送 | 审判、执行 |
| 涉案财物管理人员 | 退赔、上缴、发还 | 任意阶段 |
| 家属 | 无写入权限，仅可查询退赔进度公开视图 | — |

家属视图只含金额与状态，不含证言、主张、线索与持有人身份。
